# Бизнес-логика и Сущности

Приложение работает вокруг концепции единого централизованного хранилища данных. Логика разделена на управление независимыми справочниками и зависимыми сущностями.

## 1. Права доступа (Edit Mode)
По умолчанию приложение запускается в режиме **Только чтение**. 
- В этом режиме пользователи могут просматривать дашборд, искать технику, смотреть поэтажный план и экспортировать отчеты. Кнопки сохранения, редактирования и удаления скрыты из интерфейса.
- Для перехода в **Режим редактирования** необходимо ввести пароль (сверяется с хэшем из конфига). Вся логика изменения на стороне Go дополнительно защищена проверкой флага `a.editMode`.

## 2. Основные Сущности

### Справочники (Dictionaries)
Базовые элементы, на которые ссылаются другие сущности:
- **Отделы (Department)**: Название отдела.
- **Сотрудники (ResponsibleUser)**: ФИО и привязка к отделу.
- **Кабинеты (Room)**: Номер, название и привязка к конкретному этажу. Кабинет существует логически, даже если он еще не размещен на визуальном поэтажном плане.

### Оборудование (Equipment)
Ключевая сущность.
- **Основа**: Имеет уникальный инвентарный номер, привязку к ответственному (сотруднику) и кабинету.
- **Типы**: Разделено на типы (`pc`, `laptop`, `monoblock`, `printer` и т.д.). (Сканер исключен).
- **Общие поля**: Производитель, модель, серийный номер, а также **Сетевые настройки** (выбор статического или динамического IP и возможность указать конкретный адрес).
- **Специфичные поля**: В зависимости от типа оборудования (в UI отображаются динамически). Например, для ПК/ноутбуков/моноблоков это "ОС" и "Сетевое имя", для принтера/МФУ — "Тип картриджа" и "Тип фотобарабана". Данные хранятся в формате `map[string]interface{}` (Go) / `Record<string, unknown>` (TS).
- **Комплектующие (Component)**: Встроены прямо в карточку `Equipment`. Жесткие диски, ОЗУ, видеокарты, а также **периферия** (мониторы, ИБП) добавляются внутрь конкретного ПК и могут иметь собственные серийные номера.

### Лицензии ПО (License)
Хранятся как отдельный массив, но логически привязываются к `ResponsibleUser`. Могут быть бессрочными или иметь дату истечения (подписка).

### Поэтажный план (FloorPlan)
Система работает с 3 этажами (0, 1, 2).
- **FloorPlan**: Описывает размеры этажа (Ширина, Высота).
- **FloorPlanRoom**: Визуальное представление логического `Room` из справочника. Содержит координаты `X`, `Y`, `Width`, `Height`. Связывается с логическим кабинетом через `roomId`. Если кабинет удаляется из справочника, он должен исчезать с плана.

## 3. Генерация Отчётов
Выполняется на стороне Go через библиотеку `excelize/v2`.
React передает список отфильтрованных ID (или пустой массив для выгрузки всего), Go проходится по данным, маппит ID комнат и пользователей в читаемые строки и формирует нативный `.xlsx` файл. Диалог сохранения также вызывается на стороне ОС через Go.
