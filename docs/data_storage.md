# Хранение данных (JSON Storage)

Система изначально проектировалась с прицелом на возможность совместного использования одного JSON-файла с общего сетевого диска без необходимости поднимать выделенный сервер СУБД. Это достигается за счет нескольких механизмов защиты.

## Формат данных
Весь проект хранится в едином файле (структура `models.DataStore`). 
Он включает в себя системные поля:
- `version` (int) — счётчик версии файла (используется для optimistic concurrency).
- `lastModified` — дата и время последнего изменения.
- `modifiedBy` — кто последним внес изменения (зарезервировано для будущего).

## 1. Пессимистичная блокировка (Lock-файл)
В файле `internal/storage/jsonstore.go` реализован механизм мьютекса на уровне файловой системы.
Когда кто-то успешно вводит пароль и переходит в **режим редактирования**, система:
1. Пытается создать файл `.data.lock` в той же папке, где лежит основной JSON.
2. Если файл уже существует, значит кто-то другой (на другом ПК) уже редактирует базу. В этом случае Go возвращает ошибку, и React показывает пользователю сообщение "База редактируется другим пользователем".
3. При выходе из режима редактирования или закрытии приложения файл `.data.lock` удаляется.

## 2. Оптимистичная блокировка (Versioning)
Если lock-файл случайно завис или был удален вручную, вступает в силу проверка версии:
1. При чтении файла `JSONStore` запоминает `currentVersion`.
2. В момент вызова `Save()` система сначала читает файл с диска еще раз.
3. Если версия на диске *больше*, чем `currentVersion`, значит за это время кто-то другой успел сохранить изменения.
4. Выдается ошибка `ErrConcurrentUpdate`, предотвращающая затирание чужих данных.

## 3. Атомарная запись (Atomic Write)
Запись JSON никогда не происходит напрямую в основной файл.
Вместо этого:
1. Данные пишутся во временный файл `data.json.tmp`.
2. После успешной записи временный файл переименовывается в целевой `data.json` с помощью `os.Rename()`. 
В Linux (и большинстве файловых систем) эта операция атомарна. Если во время сохранения отключится свет, основной файл не превратится в кашу из нулевых байтов.

## 4. In-Memory синхронизация
Структура `JSONStore` внутри приложения использует `sync.RWMutex` для защиты кэшированных данных от гонок (race conditions) между разными горутинами внутри одного экземпляра приложения.
