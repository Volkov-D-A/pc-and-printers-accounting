# Архитектура приложения

Приложение построено на базе фреймворка **Wails v2**, что определяет его двухслойную архитектуру.

## 1. Backend (Go)
Отвечает за бизнес-логику, взаимодействие с ОС и безопасное хранение данных.
- **Язык**: Go 1.20+
- **Основной файл**: `app.go` — связующее звено, содержащее "Bindings" (методы, доступные фронтенду).
- **Директории**:
  - `internal/models/` — структуры данных, определяющие доменную модель (Equipment, Room, License и др.). ВАЖНО: Эти структуры зеркально дублируются в TypeScript для строгой типизации на фронтенде.
  - `internal/storage/` — логика работы с JSON (`jsonstore.go`).
  - `internal/auth/` — логика работы с хэшированием паролей (bcrypt).
  - `internal/config/` — управление настройками (путь к JSON, хэш пароля), которые сохраняются в `~/.config/pc-and-printers-accounting/config.json`.

## 2. Frontend (React + TypeScript + Vite)
Отвечает исключительно за UI/UX. Не имеет прямого доступа к файловой системе (кроме как через Wails Bindings).
- **Стек**: React 18, React Router v6, Vanilla CSS.
- **Связь с Backend**: Осуществляется через вызовы сгенерированных промисов в `wailsjs/go/main/App`.
- **Директории**:
  - `src/components/` — переиспользуемые UI компоненты (модальные окна, таблицы, сайдбар).
  - `src/pages/` — компоненты-страницы, привязанные к роутеру (EquipmentPage, FloorPlanPage и др.).
  - `src/context/` — глобальный стейт-менеджмент (`AppContext`), который хранит кэш данных (чтобы не дергать Go при каждом рендере) и статус `editMode`.
  - `src/types/` — TypeScript интерфейсы (`index.ts`), дублирующие Go-структуры.
  - `src/styles/` — глобальная дизайн-система (CSS переменные, типографика).

## Взаимодействие слоев
1. **Инициализация**: React вызывает `GetConfig()`, проверяет наличие пути к файлу и `IsFirstRun()`. 
2. **Чтение**: Если файл задан, вызывается `GetAllData()`. Go читает JSON, десериализует и отдает React в виде JS-объекта. React сохраняет его в `AppContext`.
3. **Запись**: Пользователь делает изменение в UI (например, `UpdateEquipment(eq)`). React вызывает соответствующий биндинг. Go проверяет `editMode`, вносит изменения во внутренний кэш и записывает JSON на диск.
4. **События**: Go может слать асинхронные события во Frontend через `runtime.EventsEmit`. Например:
   - `data:updated` — сигнализирует о том, что JSON-файл был изменён извне (другим пользователем в сети).
   - `auth:editModeChanged` — сигнализирует об изменении статуса блокировки (таймаут или выход).
